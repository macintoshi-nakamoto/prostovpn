# Вход по логину и паролю

Что добавлено в клиент поверх исходного AmneziaVPN и как это собрать.

## Как это работает

Приложение открывается экраном входа. Человек вводит логин и пароль,
выданные в панели, — приложение идёт на `POST /api/v1/login`, получает
токен и список стран вместе с готовыми конфигами. Конфиги уходят прямо в
штатный импорт и дальше в туннель.

На экране остаётся только страна с городом. Ни адреса сервера, ни ключа,
ни выданного адреса в подсети человек не видит: панель их и не присылает
отдельными полями, а единственное техническое поле `config` нигде не
рисуется.

Сессия хранится в `SecureQSettings` — там же, где остальные секреты
приложения. При следующем запуске экран входа не показывается: приложение
сразу спрашивает панель, не изменилось ли что-нибудь.

Раз в пять минут и при каждом запуске приложение перечитывает список
стран. Если администратор погасил сессию или кончилась подписка, панель
отвечает `401`, и приложение возвращается к экрану входа.

## Обновление приложения

Штатный `UpdateController` из AmneziaVPN ходит в их инфраструктуру, которой
мы не управляем, поэтому обновления идут через нашу панель.

При запуске приложение спрашивает `GET /api/v1/version?platform=&current=`
(без токена — обязательное обновление должно дойти и до тех, кто не вошёл).
Если версия новее, в настройках пункт подписывается «Обновить приложение —
версия X», а на его экране появляется кнопка.

Кнопка скачивает установщик и открывает его средствами системы. Он ставится
поверх: удалять приложение и входить заново не нужно.

Версии публикуются в панели, раздел «Версии». Сами файлы кладутся на сервер
в `/opt/prosto-vpn/downloads/` — nginx отдаёт их по `/downloads/`.

Сравнение версий числовое, а не строковое: иначе `2.10` считалась бы старее
`2.9`, и приложение предлагало бы «обновиться» назад при каждом запуске.

## Android

Отдельной работы не потребовалось: `cmake/android.cmake` собирает те же
исходники, что и десктоп, а платформенные файлы только добавляются. QML и
C++ общие, поэтому вход и обновление работают одинаково. Платформа в запросе
берётся из `Constants::PLATFORM_NAME` — в панели сессия видна как `android`.

В `CMakeLists.txt` править нечего: `cmake/sources.cmake` собирает
`ui/controllers/*.cpp` маской, новый контроллер попадает в сборку сам.

## Адрес панели

По умолчанию `http://127.0.0.1:8000` — для проверки на своей машине. Для
своей сборки задайте адрес при конфигурации:

```bash
cmake -DPROSTO_PANEL_URL="https://panel.example.com" ..
```

Адрес можно переопределить и в рантайме — свойство `panelUrl` контроллера
пишется в защищённые настройки.

**На боевом сервере панель обязана быть за HTTPS:** токен ходит в
заголовке `Authorization`, по HTTP его читают по дороге.

## Сборка

Клиент — обычный проект Qt6 из репозитория AmneziaVPN, сборка не менялась.

Windows: Qt 6.6+ (MSVC 2019/2022), CMake 3.25+, Visual Studio с
компонентами C++, WiX для MSI.

```bash
git submodule update --init --recursive
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DPROSTO_PANEL_URL="https://panel.example.com"
cmake --build build --config Release
```

Подробности — в `README.md` и `.github/workflows/` исходного репозитория.

## Проверка без сборки

Контракт, который читает C++, проверяется тестами на стороне панели:

```bash
cd ../backend && .venv/Scripts/python.exe -m pytest tests/test_client_contract.py -q
```

Тест повторяет запросы приложения поле в поле — вход, список стран, выход,
реакцию на погашенную сессию — и отдельно следит, чтобы в ответ не
просочились адрес сервера и ключ.

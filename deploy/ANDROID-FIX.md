# Нестабильное подключение на Android: что сделано и что осталось

Разбор жалобы «подключается раз в день, у некоторых вообще никогда».
Здесь только выводы и порядок действий; обоснования — в коммитах.

## Что показали боевые данные

Смотрели через админский API (`/api/admin/keys`, `/api/admin/users/{id}`),
18 августа 2026.

| Кто | Устройство | Версия | Ключи | Рукопожатия |
|---|---|---|---|---|
| dima | HUAWEI MNA-LX9 | 1.1.1 | есть | работает, 9 ГБ |
| EvgeniyChopa | Android | — | есть | работает, 5 ГБ |
| **maks_on** | **Samsung SM-A175F** | **1.1.3** | **созданы** | **НОЛЬ** |

Остальные «никогда» — люди без единой Android-сессии: они заходили только
из бота и веба, приложение не ставили. Их считать нельзя.

Главное из таблицы: **Huawei работает, а Samsung — нет**. Значит дело не в
оболочке и не в обфускации. Человек полчаса провёл в приложении, ключи ему
завели при входе, а на узел не пришло ни одного валидного пакета.

Конфиг, который получает клиент (расшифрован из ссылки `vpn://`):

```
Jc=10, Jmin=39, Jmax=628, S1=27, S2=140, H1..H4 — свои
MTU=1280, DNS=1.1.1.1,1.0.0.1, AllowedIPs=0.0.0.0/0,::/0
Endpoint=45.151.106.253:51820, PersistentKeepalive=25
```

Параметры обфускации корректны: `Jmin < Jmax`, `Jc` в пределах нормы,
`S1 + 56 ≠ S2` (83 ≠ 140 — иначе пакеты рукопожатия совпали бы по длине),
`H1..H4` различны и больше четырёх. То есть ломаться тут нечему.

Остаётся порт. **51820 — канонический порт WireGuard**, и часть операторов
не пропускает его вовсе.

## Две разные поломки

1. **«Раз в день»** — в приложении некому было держать туннель. Проверка
   живости жила в ViewModel экрана и умирала вместе с ним; автоподключения
   не было вовсе; смену сети никто не отслеживал. Любая помеха обрывала VPN
   до следующего ручного нажатия. — **Починено в коде, нужна пересборка APK.**

2. **«Никогда»** — единственный порт. — **Чинится на сервере, без обновления
   приложения.**

## Что уже сделано на сервере 18 августа

Шаги 1-3 ниже **выполнены и проверены**, переписывать их не нужно — они
оставлены как описание того, что стоит на машине, и как это откатить.

* запасные порты добавлены: UDP 443, 2408, 8443 → 51820, юнит
  `prosto-extra-ports.service` восстанавливает их после перезагрузки;
* доступность портов снаружи подтверждена: пробные пакеты с физического
  адаптера (мимо туннеля) увеличили счётчики всех трёх правил DNAT;
* бэкенд выкачен, колонки `servers.alt_ports` и `user_keys.endpoint_port`
  созданы миграцией, тесты на боевом венве проходят;
* поле «Запасные порты» узла заполнено: `443,2408,8443`;
* проверено на живых данных: у `maks_on` (ни одного рукопожатия) порт идёт
  по кругу `51820 → 443 → 2408 → 8443`, у работающих устройств `dima`
  порт закреплён на 51820 и не меняется.

Осталась только пересборка APK — см. последний раздел.

### 1. Добавить запасные порты

```bash
sudo bash deploy/extra-ports.sh
```

Оставляет 51820 как есть и заворачивает на него UDP 443, 2408 и 8443
правилом DNAT. Порт 443 выбран первым не случайно: по UDP он неотличим от
QUIC, и резать его целиком операторы не станут. TCP/443 у nginx это не
трогает — правило только для UDP.

Проверить: `sudo bash deploy/extra-ports.sh --status`
Откатить: `sudo bash deploy/extra-ports.sh --close`

### 2. Выкатить бэкенд

В нём появились: поле `alt_ports` у сервера, `endpoint_port` у ключа и
подбор порта для тех, у кого рукопожатия не было ни разу.

```bash
# из чекаута репозитория
scp -r backend/app/* root@45.151.106.253:/opt/prosto-vpn/backend/app/
ssh root@45.151.106.253 'chown -R prostovpn:prostovpn /opt/prosto-vpn/backend/app \
  && systemctl restart prosto-panel && systemctl is-active prosto-panel'
```

Колонки досоздадутся сами при старте (`app/migrations.py`).

### 3. Прописать порты в панели

Панель → Серверы → узел → «Запасные порты» → `443, 2408, 8443` → Сохранить.

С этого момента:

* приложения, которые уже стоят у людей, начинают получать другой порт в
  конфиге — но только те ключи, у которых рукопожатия не было НИ РАЗУ.
  У кого работает, порт не меняется никогда;
* смена происходит раз в три минуты по кругу, приложение перечитывает
  конфиг при входе и раз в минуту на экране;
* как только рукопожатие случилось, сработавший порт закрепляется за ключом.

### 4. Проверить, что помогло

```bash
# пакеты на узел приходят даже когда клиент стучится на 443
sudo tcpdump -ni any udp port 51820 -c 5

# кто ожил: смотрим ключи с нулевым трафиком
curl -s https://prostovpn.cc/api/admin/keys?limit=200 -H "Authorization: Bearer ТОКЕН" \
  | python3 -c "import sys,json;[print(k['login'],k['deviceId'] or '—',k['lastHandshakeAt']) for k in json.load(sys.stdin)]"
```

Ориентир: у `maks_on` должно появиться первое рукопожатие.

## Выпущено

**ProstoVPN 1.1.4 (versionCode 24)** собран, подписан и опубликован 18 августа.

* ключ подписи нашёлся на самом сервере — `/root/prosto-backup/prostovpn-release.jks`;
  отпечаток SHA-256 `008333…83ec` совпал с подписью выпущенного 1.1.3, то есть

* недостающий `awg-tunnel.aar` восстановлен: Java-исходники модуля `tunnel` из
  репозитория Amnezia плюс нативные библиотеки из уже выпущенного APK 1.1.3.
  Совместимость сверена по символам JNI (`awgTurnOn`, `awgVersion` и ещё
  четыре) — движок amneziawg-go v3.0.1. Рецепт: `client/android/tools/build-awg-aar.sh`;
* выложено как **необязательное** обновление: версия не проверена на живом
  телефоне, а у принудительного обновления нет пути назад.

Откат: зарегистрировать 1.1.3 обратно (файл `ProstoVPN-1.1.3.apk` на месте) или
снять 1.1.4 с публикации в панели.

## Как пересобрать APK

Правки клиента лежат в `client/android`, версия поднята до **1.1.4 (код 24)**.
Собрать их я не смог: в репозитории нет `app/libs/awg-tunnel.aar` (он вне
репозитория) и нет релизного ключа `prostovpn-release.jks`. Без ТОГО ЖЕ ключа
обновление не встанет поверх установленного — Android не принимает смену
подписи.

Код проверен компиляцией против заглушки библиотеки с той же поверхностью API
и unit-тестами на подмену порта. Это ловит ошибки типов и логики разбора
конфига, но не заменяет запуск на живом телефоне.

```bash
cd client/android
# положить awg-tunnel.aar в app/libs/ и keystore.properties в корень
./gradlew assembleRelease -PpanelUrl=https://prostovpn.cc
```

Дальше — выложить APK и зарегистрировать релиз в панели. Страницы инструкции
и лендинг берут ссылку живой из `/api/v1/downloads`, править их руками не
нужно: как только релиз опубликован, ссылка меняется сама.

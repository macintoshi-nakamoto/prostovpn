# Развёртывание на сервере

Два скрипта. Первый ставит панель, второй делает эту же машину первым
VPN-сервером. Оба можно запускать повторно.

## Что нужно знать заранее

**С машины, где писался проект, SSH наружу не работает** — порт 22 закрыт
на сетевом уровне (проверено: недоступен и `github.com:22`). Поэтому
попасть на сервер придётся одним из способов:

1. **Веб-консоль хостера (VNC)** — работает всегда, ничего не требует.
2. **SSH с другой сети** — телефон в режиме модема, другой провайдер.
3. **SSH через порт 443**, если хостер такое предлагает.

Проверить, работает ли SSH из вашей сети:

```bash
ssh -o ConnectTimeout=10 root@<адрес-сервера>
```

Если `Connection timed out` — порт 22 закрыт, используйте веб-консоль.

## Порядок

### 1. Доставить код на сервер

Через веб-консоль удобнее всего забрать код из git. Заведите приватный
репозиторий, отправьте туда проект с рабочей машины:

```bash
cd C:\vpn-panel
git remote add origin <адрес-вашего-репозитория>
git push -u origin main
```

И на сервере:

```bash
apt-get update && apt-get install -y git
git clone <адрес-вашего-репозитория> /root/prosto-vpn
```

Если репозиторий заводить не хочется — папку можно перекинуть по SCP с той
машины, где SSH работает:

```bash
scp -r C:\vpn-panel root@<адрес-сервера>:/root/prosto-vpn
```

### 2. Поставить панель

```bash
cd /root/prosto-vpn
sudo bash deploy/bootstrap.sh
```

С доменом (тогда сразу будет нормальный сертификат):

```bash
sudo bash deploy/bootstrap.sh panel.example.com
```

Скрипт ставит Python, Node и nginx, собирает панель, генерирует секреты,
заводит службу `prosto-panel`, включает HTTPS и файрвол. В конце печатает
логин и пароль администратора — **запишите их сразу**.

### 3. Сделать этот сервер первым VPN-сервером

```bash
sudo bash deploy/setup-awg.sh "Нидерланды" "Амстердам" NL
```

Ставит AmneziaWG, генерирует ключи сервера и параметры маскировки,
поднимает интерфейс `awg0` с NAT и регистрирует сервер в панели.

Панель добавляет и снимает пиров по SSH — даже на самой себе: так у неё
один способ работы и со своими серверами, и с чужими. Для этого создаётся
отдельный ключ, и в `authorized_keys` он записывается с ограничением
`from="127.0.0.1"` — снаружи им воспользоваться нельзя.

### 4. Проверить

```bash
systemctl status prosto-panel      # панель
systemctl status awg-quick@awg0    # туннель
awg show awg0                      # пиры и трафик
journalctl -u prosto-panel -f      # логи
```

Откройте `https://<адрес-сервера>/admin`, войдите, создайте пользователя —
ключ на этот сервер выдастся ему сразу. Корень домена занят публичным
сайтом, панель живёт на `/admin`.

### 5. Включить приём оплаты

Пока `PANEL_PAYMENT_PROVIDER=mock`, сайт работает целиком, но деньги не
приходят: страница оплаты честно написана как демонстрационная, и любой
посетитель может «оплатить» себе подписку. Выпускать так наружу можно
только сознательно — например, чтобы показать сервис до подписания
договора с платёжным сервисом.

Подробности — в разделе «Приём оплаты» ниже.

## После установки — обязательно

**Смените пароль root.** Он был передан в переписке открытым текстом:

```bash
passwd root
```

**Перейдите на вход по ключу и выключите вход по паролю:**

```bash
# на своей машине
ssh-keygen -t ed25519 -f ~/.ssh/prosto
ssh-copy-id -i ~/.ssh/prosto.pub root@<адрес-сервера>

# на сервере, после того как убедились, что вход по ключу работает
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh
```

**Смените пароль администратора панели** — тот, что напечатал установщик,
годится как первый, но он лежит в `.env` открытым текстом.

**Заведите домен.** Без него сертификат самоподписанный, и браузер будет
показывать предупреждение на каждом входе. С доменом:

```bash
sudo bash deploy/bootstrap.sh panel.example.com
```

## Приём оплаты

Всё настраивается в `backend/.env`. После правок:
`systemctl restart prosto-panel`.

### ЮKassa

```ini
PANEL_PAYMENT_PROVIDER=yookassa
PANEL_YOOKASSA_SHOP_ID=...
PANEL_YOOKASSA_SECRET_KEY=...
PANEL_SITE_URL=https://example.com
```

В личном кабинете ЮKassa укажите адрес для уведомлений:

```
https://example.com/api/v1/billing/webhook/yookassa
```

и включите события `payment.succeeded`, `payment.canceled`,
`refund.succeeded`.

ЮKassa **не подписывает** уведомления. Панель проверяет подлинность двумя
способами: адрес отправителя из опубликованного списка сетей и повторный
запрос платежа через API по вашим ключам. Второй — главный, поэтому ключи
обязательны: без них уведомление принимается только по адресу, и об этом
пишется предупреждение в лог.

### CryptoCloud

```ini
PANEL_PAYMENT_PROVIDER=cryptocloud
PANEL_CRYPTOCLOUD_API_KEY=...
PANEL_CRYPTOCLOUD_SHOP_ID=...
PANEL_CRYPTOCLOUD_SECRET=...
```

Адрес для уведомлений:

```
https://example.com/api/v1/billing/webhook/cryptocloud
```

`PANEL_CRYPTOCLOUD_SECRET` обязателен — им проверяется подпись уведомления.
Без него панель откажется принимать уведомления вообще: принять
неподтверждённое сообщение об оплате значит раздать доступ кому угодно.

### Проверить, что вебхук доходит

Раздел «Заказы» в панели показывает сырой поток уведомлений: пришло ли,
сколько раз и чем закончилось. Если заказ висит в `pending`, а уведомлений
нет — проблема между провайдером и nginx; если уведомления есть, а итог
`amount_mismatch` — сумма в уведомлении не совпала с заказом.

Заказ, деньги за который получены, а вебхук не дошёл, выдаётся кнопкой
«Выдать вручную». Это действие записывается в журнал.

## Письма

Письмо с логином и паролем, отправленное напрямую с VPS без SPF, DKIM и
DMARC, уходит в спам почти гарантированно. Варианта два.

### Свой домен через SMTP

```ini
PANEL_MAIL_PROVIDER=smtp
PANEL_MAIL_FROM=no-reply@example.com
PANEL_SMTP_HOST=smtp.example.com
PANEL_SMTP_PORT=587
PANEL_SMTP_USER=...
PANEL_SMTP_PASSWORD=...
```

### Транзакционный сервис

```ini
PANEL_MAIL_PROVIDER=resend
PANEL_RESEND_API_KEY=...
```

### DNS-записи — обязательно

Три записи на домене отправителя. Без них письма фильтруются независимо от
того, чей сервер их отправил.

| Тип | Имя | Значение |
|---|---|---|
| TXT | `@` | `v=spf1 include:<домен-отправителя> ~all` |
| TXT | `resend._domainkey` (имя даёт сервис) | ключ DKIM из панели сервиса |
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com` |

Проверить после настройки: отправьте письмо на `check-auth@verifier.port25.com`
или воспользуйтесь mail-tester.com — оба покажут, проходят ли SPF и DKIM.

Тема письма намеренно не содержит слова «VPN»: российские почтовые службы
фильтруют такие письма охотнее. Внутри — только логин, пароль и ссылки на
скачивание; ключей, конфигураций и вложений в письме нет.

### Если письмо не ушло

Очередь доставки видна в разделе «Заказы»: там же кнопка «Отправить
снова». Задание с исчерпанными попытками показывается отдельным блоком —
это ровно те случаи, когда человек заплатил, а доступ до него не дошёл.

## Обновление

```bash
cd /root/prosto-vpn && git pull
sudo bash deploy/bootstrap.sh          # или с доменом
```

Секреты и база при повторном запуске не трогаются. Схема базы
доводится до актуальной при старте: недостающие таблицы, колонки и индексы
досоздаются сами, ничего вручную выполнять не нужно.

Одно исключение — `PANEL_SECRETS_KEY`. Если он не был задан до обновления,
при первом запуске панель зашифрует пароли, лежавшие открытым текстом, и
сотрёт исходники. Менять этот ключ после этого нельзя: старые пароли
станут нечитаемыми, и останется только сбросить их.

## Если что-то пошло не так

| Симптом | Куда смотреть |
|---|---|
| Панель не открывается | `journalctl -u prosto-panel -n 50`, `nginx -t` |
| Модуль AmneziaWG не загрузился | `dkms status`, перезагрузка после установки |
| Туннель не поднимается | `journalctl -u awg-quick@awg0 -n 40` |
| Клиент не подключается | параметры маскировки на сервере и в шаблоне обязаны совпадать |
| Панель не выдаёт ключи | в разделе «Серверы» видна ошибка SSH; проверьте `ssh -i /opt/prosto-vpn/.ssh/panel_ed25519 root@127.0.0.1 true` |
| Заказ висит в «ждёт оплаты» | «Заказы» → «Уведомления провайдера». Пусто — вебхук не доходит: проверьте адрес в кабинете провайдера и что nginx пропускает `/api/v1/billing/webhook/` |
| Заказ отклонён по сумме | цену тарифа поменяли между оформлением и оплатой. Сумма в заказе зафиксирована, и это правильно: выдайте вручную, если деньги получены |
| Письмо не пришло | «Заказы» → блок «Недоставленные письма», там же причина от почтового сервиса и кнопка повтора |
| «Показать пароль» не работает | `PANEL_SECRETS_KEY` не задан или изменился. Изменившийся ключ не восстановить — остаётся сбросить пароль |
| На сайте нет тарифов | тариф должен быть и «доступен для новых подписок», и «показывать на сайте», и с ценой больше нуля |

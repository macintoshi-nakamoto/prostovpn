# Почему «вошёл, а VPN не работает» — и как это починить

Разбор конкретной поломки и порядок действий на боевом сервере.

## Что происходит на самом деле

Человек оплачивает, получает логин и пароль, вводит их в приложении — вход
проходит успешно. И дальше ничего. Ни ошибки, ни объяснения.

Причин ровно две, и обе не в приложении.

### 1. На сервере стоит старая панель

Проверяется одним запросом к панели:

```
GET /openapi.json  →  "version": "2.0.0"
```

Версия 2.0.0 — это сборка до всего, что связано с продажами. В ней **нет**:

| Чего нет | Чем это отзывается |
|---|---|
| `/api/v1/plans`, `/api/v1/orders`, `/api/v1/billing/webhook/*` | купить через сайт невозможно в принципе |
| `/api/v1/version` | кнопка обновления в приложении не работает |
| `/api/admin/orders`, `/api/admin/audit` | в панели нет разделов «Заказы» и «Журнал» |
| `/api/admin/releases` | нечем управлять версиями приложения |

Проверить, что стоит у вас, можно одной командой:

```bash
curl -sk https://ваш-домен/openapi.json | grep -o '"version":"[^"]*"' | head -1
```

Должно быть `2.1.0` или новее. Если `2.0.0` — код не обновлён.

### 2. Нет ни одного рабочего VPN-узла

Это и есть непосредственная причина «ничего не работает». Приложение
входит, спрашивает список серверов и получает пустой массив — потому что
выдавать нечего.

Так выглядела локальная база: шесть узлов, и **все шесть**
демонстрационные, с адресами из RFC 5737 (`192.0.2.0/24`,
`198.51.100.0/24`, `203.0.113.0/24`). Эти диапазоны зарезервированы под
примеры в документации и не маршрутизируются никуда. Панель показывала их
включёнными и зелёными, потому что умела только «включён», а «работает» —
не умела.

Посмотреть, что в базе:

```bash
cd /opt/prosto-vpn/backend && .venv/bin/python tools/purge_demo_servers.py
```

Скрипт печатает демонстрационные узлы отдельно от настоящих и прямо
говорит, если настоящих нет. Удаляет только с `--apply`.

## Что изменилось в коде, чтобы это не повторилось

1. **Панель не отдаёт клиентам узлы с документационными адресами.** Такой
   узел — всегда забытые демо-данные. Показать его хуже, чем не показать:
   человек видит страну в списке, жмёт «подключиться» и получает вечное
   ожидание вместо понятного сообщения.

2. **API объясняет пустой список.** `/api/v1/login` и `/api/v1/servers`
   возвращают поле `notice` с причиной: «Подписка закончилась»,
   «Серверы настраиваются», «Готовим подключение, это займёт около минуты».
   Раньше приходил пустой массив без единого слова.

3. **Кнопка «Проверить» в разделе «Серверы».** Панель идёт на узел: адрес,
   UDP-порт, SSH, поднят ли `awg0`, — и пишет человеческим языком, что не
   так. Результат попадает в карточку сервера.

4. **Тревога на сводке.** Пока ни один узел не может выдать конфиг, поверх
   выручки висит красный блок «Клиенты не могут подключиться». Это самая
   дорогая поломка сервиса и при этом самая незаметная: раньше её было
   видно только по тому, что перестали приходить деньги.

## Порядок на сервере

Всё выполняется на сервере панели — через веб-консоль хостера или SSH.

### Шаг 1. Забрать код

```bash
cd /root/prosto-vpn && git pull
```

Если репозиторий там не заведён — залейте проект заново, как описано в
[README.md](README.md).

### Шаг 2. Обновить панель

```bash
sudo bash /root/prosto-vpn/deploy/bootstrap.sh
```

Скрипт можно запускать повторно: секреты и база не перезатираются.
Он поставит зависимости, соберёт панель, скопирует сайт и перезапустит
службу. Схема базы дойдёт до актуальной сама при старте.

**До первого запуска новой версии** проверьте, что в
`/opt/prosto-vpn/backend/.env` задан `PANEL_SECRETS_KEY`. Если его нет,
`bootstrap.sh` сгенерирует. Менять его потом нельзя: им шифруются пароли
клиентов.

Проверка:

```bash
curl -sk https://ваш-домен/openapi.json | grep -o '"version":"[^"]*"' | head -1
```

### Шаг 3. Завести настоящий VPN-узел

Без этого шага всё остальное бессмысленно: продавать доступ, которого нет,
нельзя.

```bash
sudo bash /root/prosto-vpn/deploy/setup-awg.sh "Нидерланды" "Амстердам" NL
```

Скрипт ставит AmneziaWG, поднимает `awg0` с NAT, генерирует параметры
маскировки и регистрирует узел в панели. Панель заводит и снимает пиров по
SSH — в том числе на самой себе, через ключ с ограничением
`from="127.0.0.1"`.

Проверка:

```bash
systemctl status awg-quick@awg0
awg show awg0
```

Затем в панели: **Серверы → Проверить**. Должно быть «Узел рабочий».

### Шаг 4. Убрать демо-узлы

```bash
cd /opt/prosto-vpn/backend
.venv/bin/python tools/purge_demo_servers.py            # посмотреть
.venv/bin/python tools/purge_demo_servers.py --apply    # удалить
```

И выключить их источник, иначе они вернутся в пустую базу:

```ini
PANEL_SEED_DEMO=0
```

### Шаг 5. Проверить путь клиента целиком

```bash
curl -sk -X POST https://ваш-домен/api/v1/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"pv0000000","password":"пароль"}' | python3 -m json.tool
```

Смотреть на два поля:

* `servers` — должен быть непустым;
* `notice` — если он есть, там написано, чего не хватает.

Пустой `servers` вместе с `notice` — это уже не молчание, а диагноз.

### Шаг 6. Обновить версию приложения в панели

Раздел **Версии**: платформа, номер, ссылка на установщик, размер и
контрольная сумма. Приложение спросит её при запуске и предложит
обновиться.

Контрольная сумма обязательна: клиент отказывается ставить обновление,
если панель её не прислала или она не совпала. Установщики кладутся в
`/var/www/downloads/`, откуда их раздаёт nginx.

## Куда смотрит приложение

Адрес панели в репозитории не хранится: он принадлежит установке, а не
коду. Сборка берёт его из параметра, а по умолчанию подставляет заведомо
нерабочий `https://panel.example.com` — чтобы забытый параметр было видно
сразу, а не после выкладки.

```bash
./gradlew packageMsi packageExe -PpanelUrl=https://ваш-домен
```

В GitHub Actions адрес приходит из переменной репозитория `PANEL_URL`
(Settings → Secrets and variables → Actions → Variables).

Обязательно домен, а не голый IP: на IP публичный сертификат не
выпускается, а с самоподписанным клиент обрывает соединение до запроса —
вход молча не проходит.

## Короткий чек-лист

- [ ] `openapi.json` отдаёт версию `2.1.0` или новее
- [ ] в разделе «Серверы» есть узел с настоящим адресом
- [ ] «Проверить» по нему говорит «Узел рабочий»
- [ ] на сводке нет красного блока «Клиенты не могут подключиться»
- [ ] `tools/purge_demo_servers.py` не находит демонстрационных узлов
- [ ] `PANEL_SEED_DEMO=0`
- [ ] вход тестовой учёткой возвращает непустой `servers`
- [ ] приложение собрано с вашим `PROSTO_PANEL_URL`

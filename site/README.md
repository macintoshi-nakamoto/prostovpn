# site — публичный сайт Prosto

Статические страницы. Ни сборки, ни зависимостей, ни node_modules: сайт
можно открыть двойным щелчком по `index.html`, положить на любой хостинг
или отдавать тем же приложением, что и API.

## Почему без фреймворка

Всё содержимое сайта — семь страниц текста и три формы. Сборка добавила бы
к ним шаг «сначала соберите», отдельный каталог `dist`, который нужно не
забыть пересобрать, и полтораста килобайт рантайма ради `<h1>`. Динамики
здесь ровно на четыре небольших модуля, и они пишутся на том же языке,
на котором выполняются.

Внешних скриптов нет ни одного, и это не про размер. Сайт продаёт
приватность; запрос к чужому домену на его страницах противоречил бы
тексту, который на этих страницах написан.

## Страницы

| Файл | Что это |
|---|---|
| `index.html` | Лендинг: одна мысль на экран, тарифы из базы |
| `checkout.html` | Выбор тарифа и почта → создание заказа |
| `pay.html` | Демонстрационная оплата (только при `PANEL_PAYMENT_PROVIDER=mock`) |
| `success.html` | Ожидание подтверждения и показ логина с паролем |
| `download.html` | Установщики; ссылки берутся из раздела «Версии» панели |
| `account.html` | Личный кабинет: срок, устройства, продление, смена пароля |
| `offer.html`, `privacy.html`, `contacts.html` | Документы и поддержка |
| `404.html` | Ненайденная страница |

## Что нужно заполнить перед запуском

1. **`contacts.html`** — адрес почты и Telegram поддержки. Сейчас там
   `support@example.com`: на него будут писать живые люди, у которых не
   работает оплаченный доступ.
2. **`offer.html`** и **`privacy.html`** — реквизиты в квадратных скобках,
   сроки возврата, дата редакции. Платёжные сервисы проверяют оферту при
   подключении и отказывают, если реквизитов нет.
3. **Список стран** в бегущей строке `index.html` — под те серверы, которые
   реально добавлены в панели.

Цены заполнять не нужно и нельзя: они приходят из `/api/v1/plans`. Цена,
записанная в вёрстке, разойдётся с той, по которой выставлен счёт, — молча
и в худший момент.

## Правило, которое нельзя нарушить

Пользователь за весь жизненный цикл видит **логин и пароль** — и больше
ничего. Ни ключей, ни файлов конфигурации, ни ссылок `vpn://`, ни QR-кодов
ни на одной странице, ни в письме, ни в приложении.

Проверка:

```bash
grep -riE '(private|preshared)key|vpn://|wg-quick' site/
```

Пусто — значит правило соблюдено.

## Локальный запуск

Проще всего вместе с бэкендом — тогда работают тарифы, оплата и кабинет:

```bash
cd backend && PANEL_SITE_DIR=../site .venv/bin/uvicorn app.main:app --reload
```

Сайт откроется на `http://127.0.0.1:8000`, панель — на `/admin`.

Только вёрстку можно смотреть и так, но запросы к API упрутся в отсутствие
сервера:

```bash
cd site && python -m http.server 5500
```

## Структура

```
assets/css/site.css   вся вёрстка, включая токены цветов и адаптив
assets/js/site.js     появление при прокрутке, курсор, меню, копирование
assets/js/api.js      запросы к API, форматирование денег и дат
assets/js/plans.js    тарифы на главной
assets/js/checkout.js создание заказа
assets/js/pay.js      демонстрационная оплата
assets/js/success.js  опрос статуса заказа и показ доступа
assets/js/download.js ссылки на установщики
assets/js/account.js  личный кабинет
```

Оформление — тёмная тема и один акцентный цвет (`--accent`). Второго
акцента нет намеренно: как только их два, ни один больше ничего не
выделяет. Поменять фирменный цвет можно одной строкой в `:root`.
